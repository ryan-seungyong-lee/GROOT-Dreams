# IDM으로 액션 라벨을 만들 때 반드시 할 것 — 청크 평균 + 약한 스무딩

> 이 문서는 2026-08-09 `rldx1-ft-v4-both/checkpoint-20000` 롤아웃 실패를 진단하다 나온 결론입니다.
> 진단 전체: `project/anyh2r/h2r_diag/REPORT.md`

## 한 줄

**IDM은 매 프레임 H-step 청크를 예측하는데 우리는 step 0 하나만 쓰고 H−1개를 버리고 있었다.**
그 결과 라벨에 프레임마다 독립인 잡음이 남았고, 그 잡음의 크기가 **프레임 사이의 진짜 움직임보다 컸다.**
VLA는 그 잡음까지 모방하도록 학습돼서 롤아웃에서 눈에 보이게 떨었다.

## 무엇이 잘못됐었나

`dump_idm_actions_h2r.py`, `dump_idm_traj_openarm.py` 둘 다 이 패턴이었습니다.

```python
chunk = reassemble(un, action_parts, H)   # (H, 28) — H=20 스텝 전부 들어 있음
idm[t] = chunk[0]                          # ← 1개만 쓰고 19개 버림
```

IDM은 프레임 `(t, t+H)` 두 장을 보고 `a[t] … a[t+H-1]`을 예측합니다. `stride=1`로 훑으면
**프레임 u는 `t' ∈ [u-H+1, u]`인 청크 H개에 전부 등장합니다.** 즉 프레임마다 최대 20개의
독립적인 추정치가 이미 계산돼 있었는데 1개만 쓰고 있었습니다.

## 왜 치명적인가 — 실측값

`idm_h2r_v4form-right` (366 ep / 140,534 frame) vs `openarm-teleop-v4-rldx-v2`, 오른팔 기준:

| 지표 | 실제 teleop | IDM 라벨 (step-0만) | 뜻 |
|---|---|---|---|
| 속도 lag-1 자기상관 | **+0.44** | **−0.11** | 궤적에 관성이 없음 = 백색잡음/톱니 |
| 속도 부호 반전율 | **2.6%** | **55.6%** | 동전 던지기(50%)와 같음 |
| 프레임당 \|Δq\| | 0.0030 rad | 0.0105 rad | 잡음으로 3.5배 부풀어 있음 |
| EE 속도 중 지터 비율 | 4% | **52%** | 속도의 절반이 가짜 |
| 가속도 평균 | 1.30 rad/s² | 6.91 rad/s² | |

핵심 수치 두 개:

- **IDM 단일 시점 오차 ≈ 0.047 rad.** (같은 에피소드를 좌/우 뷰로 각각 라벨링해 비교한 값
  0.0666 rad ÷ √2. 이 체크포인트의 실제 teleop 테스트 MAE 0.0428 rad과 거의 같음.)
- **20 Hz에서 프레임 사이의 진짜 움직임 ≈ 0.004 rad/joint.**

**잡음이 신호보다 2배 이상 큽니다.** 그래서 "이번 프레임에 어느 쪽으로 움직였나"의 부호가
사실상 랜덤이 됩니다. 이게 lag-1 −0.11, 부호 반전 55.6%의 정체입니다.

> **주의: IDM이 못 만든 게 아닙니다.** MAE 0.043 rad은 평가 기준으로는 합격입니다.
> 문제는 그 오차가 **프레임마다 독립**이라는 것입니다. 평가에서는 평균되어 사라지지만,
> 모방학습 라벨로 쓰면 정책이 그 고주파를 그대로 배웁니다.
> **IDM 라벨을 쓸 때는 MAE만 보지 말고 반드시 lag-1 자기상관과 부호 반전율을 같이 보세요.**

## 무엇을 하도록 고쳤나

`scripts/idm_chunk_fusion.py` (공용 모듈) + 두 dump 스크립트.

### (b) 청크 중첩 평균 — 추가 forward pass 0회

`ChunkAccumulator`가 프레임 u를 덮는 모든 청크의 해당 step 값을 더해 개수로 나눕니다.
이미 계산해서 버리던 값을 쓰는 것이므로 **GPU 비용이 전혀 늘지 않습니다.**

- 에피소드 앞뒤 H 프레임은 모이는 개수가 1→H로 램프업하므로 평활 효과가 약합니다.
  의도된 동작입니다. 없는 정보를 지어내지 않습니다.
- `--stride`는 반드시 `<= H`. 아니면 덮이지 않는 프레임이 생겨 `ChunkAccumulator`가 에러를 냅니다.
- 청크 내부 20 step에 가중치는 두지 않았습니다(균등). step 0과 step H−1은 관측 프레임에
  붙어 있고 중간은 보간이라 신뢰도가 다를 수 있지만, 측정해 본 적이 없어서 중립값을 택했습니다.
  나중에 재볼 여지가 있는 knob입니다.

**기대 효과**: 청크끼리 오차가 완전히 독립이면 √20 ≈ 4.5배 줄지만, 이웃 청크는 입력 프레임을
많이 공유하므로 실제로는 그보다 작습니다. 합성 시뮬레이션(`h2r_diag`에서 실측 잡음 크기로 재현):

| 이웃 청크 오차 상관 ρ | step-0 오차 | 청크평균 | +SG | lag-1 (step0 → 최종) |
|---|---|---|---|---|
| 0.0 (독립) | 0.0087 | 0.0021 | 0.0019 | −0.28 → **+0.99** |
| 0.5 | 0.0085 | 0.0031 | 0.0030 | −0.05 → **+0.99** |
| 0.8 (강한 상관) | 0.0086 | 0.0047 | 0.0047 | +0.12 → **+0.99** |

실측 lag-1이 −0.11이므로 ρ ≈ 0.3~0.4 → **오차 3배 감소** 정도를 기대하면 됩니다.
어느 경우든 lag-1은 음수에서 강한 양수로 회복됩니다.

### (a) 약한 Savitzky-Golay 스무딩

청크 평균 뒤에 남는 고주파를 걷어냅니다. 이동평균이 아니라 SG를 쓰는 이유:
**이동평균은 램프의 시작/끝과 그리퍼가 닫히는 계단을 뭉갭니다.** SG(polyorder=2)는 국소 2차
곡률을 보존하므로 궤적 모양과 파지 순간의 가장자리가 살아남습니다.

- 목/팔: `--smooth-window 9` (20 fps에서 0.45초)
- 손 12개 관절: `--hand-smooth-window 5` (0.25초) — 파지 타이밍이 라벨에서 제일 중요한
  가장자리라 일부러 짧게 둡니다.

## 쓰는 법

```bash
# 기본값이 곧 권장값. 아무것도 안 붙이면 청크평균 + SG(9/5)가 켜집니다.
sbatch --export=ALL,MODEL_OUTPUT_DIR=...,VIEW=right,SHARD=0,NUM_SHARDS=4 \
       IDM_dump/scripts/sbatch_dump_idm_h2r.sh

# 이미 _parts가 있는 상태에서 후처리만 바꿔 다시 돌릴 때 (_parts는 skip 캐시라 안 그러면 건너뜀)
... --export=ALL,...,EXTRA_ARGS="--overwrite"

# 예전 라벨과 정확히 A/B 하려면
python IDM_dump/scripts/dump_idm_actions_h2r.py ... --no-chunk-average --smooth-window 0 --hand-smooth-window 0
```

dump 로그에 클립마다 QC 줄이 찍힙니다. 이걸 보고 판단하세요.

```
QC r_arm | lag1 -0.114 -> +0.612 | signflip 55.6% -> 6.3% | |dq| 0.01050 -> 0.00382 rad
          (teleop reference: lag1 +0.44, signflip 2.6%, |dq| 0.0030)
```

**lag-1이 여전히 음수면 후처리가 부족한 것입니다.** `--smooth-window`를 올리세요.
반대로 lag-1이 +0.9를 넘고 파지 타이밍이 뭉개져 보이면 과하게 스무딩한 것입니다.

## 이걸로 해결되지 **않는** 것

스무딩은 고주파만 지웁니다. IDM 라벨에는 저주파 오차가 따로 남습니다.

같은 에피소드를 좌/우 두 뷰로 라벨링해 차이를 재면 (n=200):

```
에피소드 평균 차이 0.0362 rad
  ├ 모든 에피소드가 공유하는 global 성분  48%  (0.0172 rad)
  └ 에피소드마다 다른 성분               52%  (sd 0.0417 rad)
에피소드 내부에서도 2초 스무딩한 저주파 0.060 rad > 그 위의 고주파 0.021 rad
```

즉 **IDM의 오차는 프레임 잡음이 아니라 "이 에피소드/이 구간 동안 계속 같은 방향으로 틀린"
성분이 더 큽니다.** 어떤 시간 필터로도 못 지웁니다. 실제 피해:

`h2r`에서 파지 순간 손 방향(로봇 base 좌표계, 음수 = 손가락이 아래를 향함):

| | teleop | h2r (IDM 라벨) | 차이 |
|---|---|---|---|
| bottle | +8.8° | +9.0° | **정확** |
| ball / doll / small box | −9.6° / −14.1° / −14.9° | +15.2° / −0.1° / −3.8° | **10~25° 틀림** |
| bottle vs 나머지 대비 | **21.8°** | **7.1°** | 구분이 3배 뭉개짐 |

teleop에서는 "병은 손목을 안 꺾고 수평으로 들어가고, 나머지는 위에서 손목을 꺾어 덮는다"가
**21.8° 차이로 또렷이** 찍혀 있습니다. IDM은 병은 맞게 읽는데 **나머지를 병처럼 평평하게**
읽습니다. 이 데이터를 섞으면 "물체 종류 → 손목 자세" 매핑이 무너집니다.

**이건 별도 문제로 다뤄야 합니다.** 후보:
- IDM 학습셋에 생성 영상 도메인을 섞어 파인튜닝
- 좌/우 뷰 평균(`idm_h2r_v4form-avg`) 사용 — 랜덤 성분은 1/√2로 줄지만 global 성분(48%)은 안 줄어듦
- 파지 구간만 따로 검증/보정
- 근본적으로는 IDM 대신 비디오 생성 latent에서 액션을 바로 뽑는 구조 (mimic-video 계열)

## observation.state 도 같이 고쳤다 (2026-08-10)

IDM은 action만 내놓으므로 state는 만들어 줘야 한다. 원래는 `state[t] := action[t-1]` 이었는데
**실제 teleop에서 재보니 틀렸다.**

| 재현 모델 | neck | l_arm | r_arm | l_hand | r_hand | ALL28 |
|---|---|---|---|---|---|---|
| `state = action[t-1]` (구) | 0.0043 | 0.0108 | 0.0173 | 0.0603 | 0.1124 | 0.0443 |
| 1차 저역통과만 | 0.0043 | 0.0104 | 0.0123 | 0.0601 | 0.1039 | 0.0411 |
| **저역통과 + gain/offset** | **0.0001** | **0.0024** | **0.0057** | **0.0157** | **0.0466** | **0.0154** |

(값 = |모델 − 실제 state| 평균 rad, openarm-teleop-v4-rldx-v2 635 ep / 117,769 frame)

```
s[t]     = (1-α)·s[t-1] + α·a[t-1]      α = 0.25  (시정수 200 ms)
state[t] = GAIN·s[t] + OFFSET           관절별 상수
```

- **α**: 서보 추종 지연이 1프레임이 아니라 **4프레임(200 ms)**이었다.
  오른팔 최적 0.28, 전체 최적 0.23, 0.22~0.30 구간이 평평해서 0.25로 고정.
- **팔의 GAIN은 거의 1.0** (0.96~1.02) — 실효는 관절별 상수 **OFFSET**(0.01~0.04 rad,
  중력 처짐/영점)에서 나온다.
- **손의 GAIN은 0.30~0.98로 크게 떨어진다.** 손가락이 물체에 막혀 명령만큼 못 닫히는
  **접촉 현상**이다 (명령 > 측정인 프레임이 63%). 접촉 시점을 액션만으로 알 수 없어
  전 구간 평균 이득으로 근사했고, 그래도 오른손 잔차가 0.104 → 0.047로 절반이 된다.

**한계**: 이건 h2r의 state를 teleop의 state와 *통계적으로 닮게* 만드는 프록시다. 측정값이
아니다. 남는 0.0154 rad은 부하/백래시/접촉 타이밍처럼 액션만으로 재현 불가능한 실제 동역학이다.

**state는 `--finalize`에서 action 컬럼으로부터 다시 계산한다.** 그래서 모델을 바꾸려면
GPU 재추론 없이 finalize만 다시 돌리면 된다.

```bash
... --export=ALL,...,FINALIZE=1,EXTRA_ARGS="--state-model fitted"   # 기본값
... --export=ALL,...,FINALIZE=1,EXTRA_ARGS="--state-model prev"     # 예전 동작
```

> VLA는 **state를 입력으로 받고 action을 출력**한다 (`state` delta_indices=[0],
> `action` delta_indices=range(16), `state_dropout_prob=0.3`). 그러므로 중요한 것은
> state의 절대값이 아니라 **"state와 action의 관계"가 teleop과 h2r에서 같아지는 것**이다.

## 다음에 IDM 라벨을 만들 때 체크리스트

1. `stride <= action_horizon` 인가
2. 청크 평균이 켜져 있는가 (`--no-chunk-average`가 안 붙었는가)
3. dump 로그의 QC 줄에서 **lag-1이 양수**인가, **부호 반전율이 10% 아래**인가
4. 파지 순간 그리퍼 신호의 계단이 살아 있는가 (`--hand-smooth-window`를 너무 키우지 않았는가)
5. MAE만 보고 합격 판정하지 않았는가 — **MAE는 통과하는데 못 쓰는 라벨이 존재한다**
6. `observation.state`를 무엇으로 만들었는가 — `action[t-1]`은 실제 서보 거동과 다르다
